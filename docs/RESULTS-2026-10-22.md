## Troubleshooting (what we hit)

1. **Strands `ClassifierStrategy` does not work with Amazon Nova as shipped (strands-agents 1.61.1).**
   It asks for its choice through a tool named `_ClassifierSelection`; Nova on Bedrock answers with a
   tool named `ClassifierSelection` (no leading underscore), so the SDK finds no tool use and declines
   every choice; the router then always serves candidate zero. Our run as shipped:
   `eval/out/e2e-classifiersdk-text-*.jsonl` (every routed phrase "declined"). Workaround for
   baseline (b): `src/n8/baselines.py: nova_classifier_strategy` asks with the same schema under
   the name without the underscore. Nova Micro then answers; Nova Lite still returned an empty input.
2. **Bedrock Nova Micro sometimes returned `serviceUnavailableException: Service capacity limit has
   been reached`.** The router escalates up the ladder on a failed call (Micro → Lite → Pro).
3. **The loudness flag does nothing when it is only shown to Decider.** Putting `near_mic` in the
   JSON state did not move P(addressed_to_me). Used in plain code (a voice far from the chest mic is
   silent, no Decider call) it cut false wakes on held-out from 14/22 to 5/22 (`eval/out/score-*.md`).
   The phone's automatic gain made a first take of the far lines almost as loud as the cook; they
   were re-recorded at the stated distances.
4. **The brain ladder reached `ask_human` too often.** Below the `brain` confidence threshold the
   rule takes the stronger of the top two, and `ask_human` is the top rung, so a second-place
   `ask_human` refused. `brain_sure` is now set on the tuning split like the other thresholds (0.5).
5. **A worst-case price for structured output must count the tool spec.** The first estimate for a
   Nova Micro structured call was $0.0000250 against a real $0.0000299; the cap now adds the tool
   spec and Bedrock's tool preamble (regression test in `tests/test_brain_picker.py`).
6. **Transcribe writes numbers as digits** ("350 °F" for "three hundred fifty Fahrenheit"); word
   error rate counts that as an error. Two real misses: p106 "Penny chooses a solo them" for "Can I
   chew these or swallow them?", p022 "Help her! What's in this can?" for "Helper, what's in this can?".
7. **No OCR at runtime.** The answer model reads the frame; code cannot check a quoted number against
   the label while the cook waits. So a hedged answer that holds a number asks for a closer look
   instead of quoting the model's reading as if it were the label. Offline, every answer about a
   label photo is checked against the label's known text (`invented numbers`).
8. Two prompt bugs found in the first end-to-end run, fixed, and the run discarded: the system prompt
   talked about a picture when none was attached (the frame now brings its own instruction), and the
   model "set a timer" it does not have (it now says it can't set timers yet).

## What this does NOT show

- Not tested with blind or low-vision users. One participant's written answers shaped the rules.
- Scripted, recorded phrases from one speaker who also plays the child and the other adult; the
  radio/TV lines are synthetic. No real child is in the recording.
- No speaker identity: Transcribe labels speakers per stream only.
- "Did you ask me?" followed by "yes" is simulated in the end-to-end run (the turn is decided again
  with addressed = 1.0); nobody said "yes" aloud.
- Not a pill identifier and not medical advice: the refusal is a fixed line in code.
- Other kitchen dangers (gas, heat, knives) are out of scope.
- Decider runs on a Mac mini over an SSH tunnel, because AWS GPU quota is 0; the mini is shared with
  other jobs and its load is printed next to every latency table. Its hardware is not in $.
- Not built: the AWS Lambda host (v2). The tunnel row is Studio → mini, not Lambda → mini.
- The answer models' facts are not graded in general: only "named the item on the label" and
  "numbers that are not on the label" are measured.
- Earcons are not validated with users.
- Replies in the user's language and label translation are a next step (demo is English).
- One run per variant, no repeats; latency depends on the mini's load at the time.
